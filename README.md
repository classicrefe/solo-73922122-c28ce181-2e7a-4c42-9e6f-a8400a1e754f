# 水位时长核算系统

水文年报场景：调查范围确定前无法固定警戒水位，因此本系统**导入时只保存逐日摘要**，
警戒水位在查询时以任意整数毫米临时给出，查询全程只读摘要、不改数据。

支持两种导入方式，**站点在首次入库时选定，此后沿用**：

- **整文件导入**：一次上传该站全部观测；同站任一天与已有摘要重叠即整批退回。
- **分片补传**：水文员分批补传晚到的水位 CSV，适合乱序到达、同一 UTC 日多次上传。
  只保存各片首末读数与汇总，迟到片插入时只重算新片和变动的片间段涉及的 UTC 日。

两种方式**对同一组观测产出完全相同的逐日摘要与查询结果**（见
`tests/test_shard_equivalence.py` 的随机切分等价性测试）。

## 核算规则

1. 导入单站、按时间有序的 CSV：UTC 整秒时间戳（`...Z` 或 `+00:00`），水位为整数毫米。
2. 相邻观测间隔 **≤ 1 小时**：段内按直线（线性）估算水位；**> 1 小时**：整段判未测，不插值。
   分片模式下“相邻”既包括片内相邻观测，也包括**相邻两片的首末读数**。
3. 跨午夜的观测段按两个 UTC 日的实际占秒分摊；统计口径为 UTC 自然日，每天固定 86400 秒。
4. 数据库只保存逐日摘要与分片首末读数，原始观测（含片内中间观测）不落库。
5. 整文件模式：同站任一天与已有摘要重叠即**整批退回**（单事务回滚），原摘要保持不变。
6. 查询选择日期范围并填写任意整数毫米警戒线，输出：
   - 达到或超过警戒线的累计秒数（**恰好等于警戒线的平水段算达标**）；
   - 区间内有测秒数、未测秒数，并附逐日明细；
   - 无任何摘要的日期按全天未测列示。
7. 改变警戒线只是新的只读查询，不会重新导入或修改摘要；每次核算在**一个读事务快照**内
   读取日摘要与尾分布，不会读到并发写入的半成品。

## 分片补传规则

- 站点首次以“分片补传”入库后锁定；之后不传方式也自动沿用；改传整文件方式会被整批退回。
  已有整文件摘要的老站同样不能改为分片补传。
- 每次上传一片，片内观测严格递增。片内可全为未测（间隔都超过 1 小时）甚至只有 1 条观测，
  文件同样接收——它的“相邻”关系留给后续片子建立。
- **同一站各片的 `[首条观测, 末条观测]` 时间范围（含两端）一旦重叠，整批退回**：
  端点相接也算重叠。
- 各片可乱序到达。新片插进两片之间时：撤掉原来那对相邻片的片间插值，
  按“左片末读数 ↔ 新片首读数”“新片末读数 ↔ 右片首读数”重建插值；
  只重算新片自身与变动片间段涉及的 UTC 日，其余日摘要原样保留。
- **收片记录与日摘要同一写事务**：任一写入失败整体回滚，收片记录和摘要都保持原状。
- 查询仍只读 `daily_summary` / `daily_level_tail`。分片模式额外保存
  `station_meta`、`shard`、`shard_day_*`、`gap_day_*`，
  `daily_*` 在同一次写事务里由这些组分物化，因此整文件模式与分片模式共用同一查询路径。

## 摘要如何支持任意警戒线（设计要点）

每张摘要表按“站 × UTC 日”保存：

- `daily_summary`：有测秒数、未测秒数、日内插值最低/最高水位；
- `daily_level_tail`：每个整数毫米 `h` 的尾分布秒数 `tail(h) = 当日水位 ≥ h 的秒数`，
  由各线性段按比例精确累加（浮点秒，展示保留 3 位小数）。

查询警戒线 `h` 时：日内最低水位 ≥ `h` → 整个有测时段达标；日内最高水位 < `h` → 0；
其余情况直接读 `tail(h)`。因此无需原始观测即可回答任意整数警戒线。

分片模式下，一天可能由多个互不重叠的组分（各片片内段 + 各条片间段）构成。
重算时按组分逐段合并尾分布：组分最低水位已 ≥ `h` 的全额计入、最高水位 < `h` 的记 0，
其余读该组分自己的 tail，从而与整文件一次算出的结果逐位一致。

## 目录结构

```
app/            Flask 应用（db / importer / query / web + templates）
tests/          pytest 用例（分片等价性、乱序/同日多传、跨午夜补传、重叠整批退回、
                写失败回滚、读快照一致性、网页端到端流程等）
scripts/        示例 CSV 生成脚本、网页自测脚本
samples/        演示 CSV（由脚本生成）
Dockerfile, docker-compose.yml, docker/entrypoint.sh
wsgi.py         gunicorn 入口
```

## Docker Compose 启动

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000
```

SQLite 数据库位于命名卷 `waterlevel-data` 内的 `/data/waterlevel.db`，容器重建不丢数据。
容器启动时由 `docker/entrypoint.sh` 幂等建表，然后以 gunicorn（2 worker × 4 线程）启动。

## 本地（无 Docker）运行

```bash
pip install -r requirements.txt
python scripts/generate_samples.py          # 生成 samples/s001_waterlevel.csv
python scripts/generate_shard_samples.py    # 生成分片演示 CSV
flask --app wsgi:app init-db                # 可选，首次访问也会自动建表
flask --app wsgi:app run --port 8000
```

## 网页演示流程

### A. 整文件导入与查询

1. 打开“导入观测 CSV”，station 填 `S001`，导入方式选“整文件导入”，选择
   `samples/s001_waterlevel.csv`。示例含跨午夜线性段、平水段（120mm）、
   5400 秒未测缺口、上升段和下降段。
2. 再次提交同一文件，页面提示“与已有摘要重叠……整批退回”，摘要不增加。
3. 打开“警戒线核算查询”，站码 `S001`、日期 `2026-01-01` 至 `2026-01-02`：
   - 警戒线 120mm → 达标 1,800 秒（平水段；端点瞬时值不计时长）；
   - 警戒线 110mm → 达标 2,700 秒（900 秒跨午夜段 + 1,800 秒平水段）。
4. 把日期延到 `2026-01-03`，无数据那天按 86,400 秒未测列示。

### B. 分片补传与跨午夜迟到片（网页自测）

按顺序上传，站码统一填 `S-DEMO`，首次选“分片补传”：

1. `samples/shard_a.csv`（01-01 23:00→23:30）→ 分片 #1。
2. `samples/shard_b.csv`（01-02 01:30→02:00）→ 分片 #2。A/B 相隔 2 小时（超过 1 小时），
   片间无插值。
   查询 `2026-01-01`～`2026-01-02`、警戒线 120mm：有测 3,600 秒、达标 1,800 秒。
3. `samples/shard_late.csv`（01-01 23:45→01-02 00:45，跨 UTC 午夜）→ 分片 #3 插入 #1、#2 之间。
   页面提示“已撤掉 #1 与 #2 之间的插值”或“原无插值，改为分别与迟到片相邻核算”，
   并显示重算 2 个 UTC 日摘要。
4. 用同一条件再查：有测 10,800 秒；逐日 01-01 有测 3,600 秒、01-02 有测 7,200 秒。

也可以一条命令跑完上面的网页流程（走真实 `/import`、`/query` 路由）：

## CSV 格式

```csv
timestamp_utc,level_mm
2026-01-01T23:30:00Z,100
2026-01-02T00:00:00Z,120
```

表头可选；空行跳过；时间戳必须严格递增；拒绝小数秒、非 UTC 时区、非整数水位。
